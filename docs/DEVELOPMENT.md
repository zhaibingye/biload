## 0.1.1 Android 启动崩溃修复

0.1.0 在上述实机启动时出现 JNI 未初始化的原生崩溃：`JNI is not initialized`。检查发现 Android 的 `GeneratedPluginRegistrant.registerWith()` 是空方法，JNI 等原生插件没有注册。此前 Windows 缺少符号链接权限导致 `flutter pub get` 在生成注册文件前中断；构建脚本补建目录联接后直接以 `--no-pub` 构建，打包成功但沿用了不完整的注册文件。

构建脚本会在补建联接后重新完成 `flutter pub get`，并让 Flutter 在构建时按 debug/release 模式重新生成注册代码，避免将开发专用插件带入 release。`tool/verify_android_plugins.dart` 在构建后对照依赖元数据检查原生插件，最初修复的 release 已检查 9 个运行时插件。测试覆盖空注册文件、运行时插件齐全和 debug 开发插件缺失。0.1.0 包保留为历史产物，应使用 0.1.1 或后续修复版。

## 0.1.2 Android 通知与账号入口

实际会员下载暴露了 Android 15 的 UIDT 通知要求：系统在通知未提供时终止任务并报告 ANR（`required notification not provided`）。新安装时通知权限返回 denied，原逻辑只在 undetermined 时申请，导致请求被跳过。启动时库默认重新调度中断任务，还可能再次触发相同问题。

现在在用户新增或继续下载时检查并申请权限；未允许时不安排原生传输。启动阶段不弹权限框，相关未完成任务转为暂停，并提示开启通知；关闭插件的自动恢复，在权限具备后再恢复。每个新传输开始前再次检查权限。实机慢传输测试持续 15.9 秒并完成文件合并，覆盖了之前短测试未超过的系统通知时限。

顶部账号入口根据实际登录状态分流：未登录时打开登录对话框，已登录时切换至账号信息页并将滚动位置复位，展示头像、昵称、UID 和会员状态；切换账号与退出操作保留在该页。手机尺寸回归测试验证从长版本列表点击账号入口后，信息卡片直接可见且不打开登录对话框。

## 0.1.4 公共存储、音轨与进度

Android 默认目标改为公共 `Download/biload`。Android 10+ 通过 MediaStore.Downloads 创建待提交文件，复制并核对长度后提交；无需申请访问其他应用媒体的权限。Android 8/9 使用公共下载目录并申请最高 API 28 的存储权限。自选目录通过 ACTION_OPEN_DOCUMENT_TREE 获取持久读写授权，先写暂存文档再改名。参考 [Android 共享媒体](https://developer.android.com/training/data-storage/shared/media)、[目录授权](https://developer.android.com/training/data-storage/shared/documents-files)。

音视频先在任务工作目录下载与合并验证，保存到目标目录并持久化成功状态后清理中间数据。旧版媒体迁移持久保存原件清理凭据，确保目的文件已存在后才删除原件；异常中断可以重试。旧默认目录中未被任务记录引用的媒体文件会恢复为待迁移记录。移除任务时清理对应中间数据；启动时清理已完成/取消任务及没有记录的遗留任务缓存，手动清理还可移除失败任务缓存，暂停任务保留。

默认 DASH 选择一个视频版本和一条 AAC 音轨，合并为一个文件；整合流默认保留内嵌音频；只选择音轨时生成独立音频文件。界面在加入队列前显示文件数量和音轨合并方式。移除 Wi-Fi 专用设置及调度约束，历史设置不再阻止移动网络任务。加入队列时复位滚动位置，使新任务直接可见。

总进度采用所有所选资源的字节总和。优先使用已完成缓存的实际大小及接口大小；缺失时通过不携带账号 Cookie 的 CDN HEAD/单字节 Range 获取总长度，并用原生传输头校正。缓存字节只计一次；未知总长度时不显示伪百分比。全部流下载完毕时为 100%，合并和保存单独显示，不再预留人为比例。文件长度不一致时拒绝标记完成。

55 项测试通过，覆盖字节权重、未知大小、缓存复用、暂停恢复、CDN 长度探测、Cookie 隔离、存储提交失败、取消回滚、旧文件迁移与清理。Android 15 的 5 项原生测试报告为 `artifacts/native/20261030-012715-704/report.json`：公共文件创建/读取/删除、重复发布幂等、无记录旧文件迁移并删除原件、15.9 秒慢传输，以及用户样本 `BV19pnt6XE6d` 的完整下载、合并、字节进度与缓存清理。该匿名样本输出 8,722,425 字节，内含一个视频轨和一个音轨；所选原始流总量 8,668,016 字节，合并容器的开销不计入网络下载百分比。

## 0.1.5 Windows 登录与文件打开

原生回归复现 `desktop_webview_window 0.4.0` 的 Windows Cookie 字符串结尾包含 NUL。上游 `ConvertLPCWSTRToString` 把 WideCharToMultiByte 的终止符也保存在 std::string 中，导致域名与 SESSDATA 精确匹配失败。biload 接收层只移除尾部 NUL，拒绝嵌入控制字符，按域名和有效期筛选；会话 Cookie 不受持久 Cookie 的过期时间影响。可选刷新令牌求值增加超时和独立错误处理，不能阻止有效 Cookie 完成登录。

Windows 文件打开改为 MethodChannel 调用 ShellExecuteExW，直接传入 UTF-16 绝对路径，并区分文件缺失与系统打开错误。生成的两秒媒体包含中文、空格、#、% 文件名，原生打开请求成功，系统显示播放器选择窗口；未把出现选择器记为播放完成。真实短信验证码仍需用户回归。

60 项 Flutter 测试、静态分析、本地 WebView POST 请求保留、HttpOnly 会话 Cookie 读取及原生路径打开检查通过。测试不读取真实验证码或凭据。详细结果见 windows-login-verification-0.1.5.json。

## 1.0.0 四端运行修复

Linux 的 FFmpeg 插件以 soname 调用 dlopen，主程序的 RUNPATH 不会自动用于插件发起的加载。现在插件从自身目录加载引擎，随包的动态库设置为相邻库查找路径；运行验证不再依赖 LD_LIBRARY_PATH 掩盖分发包问题。补齐 libvpx 7、两项 AMR 兼容库及许可说明。

Linux 上游媒体信息桥接返回含空项的 streams，导致合并后轨道检查抛出类型异常。改为读取同一 FFprobe 引擎输出的原始 JSON，继续严格检查轨道、时长与起始解码，不跳过完整性检查。回归测试拒绝空轨道元数据。

桌面传输的 pause() 返回表示命令已送达，并不表示已写入续传数据。快速继续时可能错过底层暂停事件，使 macOS 任务留在暂停状态。现在等候 paused/最终事件确认，继续操作等待该过程完成，随后复用传输句柄。新增延迟暂停确认的并发回归测试。

Android 固定签名迁移保留旧证书，正式构建不再使用 CI 临时开发密钥。macOS 自选目录通过 NSOpenPanel 授权、安全书签保存与启动恢复，保留 App Sandbox；系统范围统一为 13+。版本、作者信息与发布流程统一，验证细节以正式 Release 附件为准。

发布前逐张检查截图发现 Intel macOS 的 Impeller 离屏截图全黑，原检查仅验证尺寸，未识别无内容图像。新增像素透明度和明暗范围检查，空白/纯黑/透明画面不能通过；macOS 采用 Flutter 官方支持的 `FLTEnableImpeller=false`，使用 Skia Metal 后端，并让验证窗口获得前台状态。该截图异常本身不等同于已证明真实设备窗口黑屏，后续以重新运行结果为准。

解析与分集切换已有 `parsing/adding` 互斥，因此移除不可达的代次失效判断、重复清空选择和重复版本查找。下载缓存校验统一使用一次文件 stat，状态守卫改为同步调用，结束工作线程时释放保存节流记录。Windows/Android 构建共用路径联接与依赖准备逻辑；Android 保留构建后原生插件注册检查，移除构建前重复检查和依赖已就绪后的重复联接创建。清理 pubspec 与 Linux 无操作生命周期模板。

本机验证：格式检查、静态分析、67 项 Flutter 测试通过；Windows Release 构建及打包后 15 项原生回归通过，覆盖 SQLite、系统凭据存储、UI 渲染、AVC/HEVC/AV1、AAC/FLAC/EAC3 多音轨、纯音频、暂停与 Range 续传、WebView POST 与 HttpOnly Cookie。使用独立测试账号和内存数据库的原生窗口实测标题栏图标、账号跳转、并发数 2→3 后底色消失以及标签移除；测试窗口已关闭。用户原有安装与账号数据保留。

## 2026-10-30 安装位置保存用户数据

按维护者要求，新版本从空数据开始，移除旧版任务扫描、文件迁移、迁移清理凭据及对应 UI/测试；旧目录和旧凭据均不读取、不迁移、不清理。桌面端的 `user-data` 固定在可执行文件旁（macOS 在 `.app` 旁），默认成品目录保留为各系统“下载”目录下的 `biload`，也可由用户另选目录。目录不可写时明确提示改用可写的安装位置，保留单一路径。设置页展示实际路径，提供打开文件夹与清理已结束任务缓存入口；关闭程序后删除 `user-data` 可重置个人数据。

SQLite 设置/任务与原生下载调度、暂停/续传记录都使用此目录。下载插件的临时传输目录显式设置在本地缓存下，避免另写系统临时目录。Windows WebView2 使用该目录内的专用 profile；Linux 在进程初始化时固定 GLib 的 XDG 数据/配置/缓存目录，并恢复原始环境以免影响外部播放器。macOS 便携版关闭 App Sandbox，移除系统 UserDefaults 安全书签；选定目录直接保存到本地设置，登录窗口使用不落盘的 WKWebsiteDataStore。

桌面账号采用本地加密文件：Windows 使用当前用户的 DPAPI 保护，Linux/macOS 使用 AES-GCM、随机 nonce 和当前用户独占权限的本地密钥。Windows 的加密文件通常需要在原系统用户下读取，跨电脑使用时重新登录。Android 的 APK 安装区只读，使用应用目录内新的 `user-data` 与新会话存储键，保留系统管理方式和公共下载目录；不处理旧位置残留。

移除未再使用的 url_launcher 依赖和旧 Android 文件导出通道，保留当前存储选择器与权限回调。依赖变化的实际构建暴露了 Flutter 在报告 pub get 成功后仍可能清空插件链接的情况；共享构建准备现统一创建一次目录联接，再按需补完失败的 pub get，确保插件注册完整。

本机验证范围包括：72 项自动化测试、静态分析、Windows Release 构建、安装位置与账号密文读写/覆盖/重开/清除、17 项打包程序原生回归，以及正常启动后无旧账号、设置页数据路径、中文目录的资源管理器打开。Linux/macOS 仅静态检查；Android 静态核对 8 个运行时原生插件与存储回调，未做手机测试。新分发包排除所有运行生成的 `user-data`、`downloads` 和验证数据，详情见 `portable-storage-verification.json`。
